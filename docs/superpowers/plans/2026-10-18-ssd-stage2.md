# SSD Stage 2 (data disk, local volumes, no Longhorn) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** All app state (configs and Postgres) lives on a second SSD zvol mounted by Talos, served by a `local-data` hostpath StorageClass and backed up hourly to the HDD pool; Longhorn is removed.

**Architecture:** TrueNAS zvol `tank2/talos-data` → second virtio disk of the `talos` VM → Talos `UserVolumeConfig` `data` at `/var/mnt/data` → OpenEBS hostpath class `local-data` (default). Apps move one PR at a time with a two-pass rsync into a new `<app>-data` PVC; CNPG clusters move by adding an instance on the new default class, switching over and scaling back to 1.

**Tech Stack:** Talos 1.13 (talhelper 3.1.17), FluxCD, OpenEBS localpv-hostpath, CloudNativePG (TrueCharts `cnpg.main` values), TrueNAS 25.10 midclt, bash + jq.

**Spec:** `docs/superpowers/specs/2026-10-18-ssd-storage-design.md`, section "Stage 2 in detail".

## Global Constraints

- Downtime only while **nobody is playing anything in Emby**: every step that stops an app or the node runs `scripts/emby-idle.sh` first and waits/stops if it fails.
- Emby key: Secret `emby-maintenance`, key `api-key`, namespace `media`, file `clusters/main/kubernetes/media/emby/app/emby-maintenance.secret.yaml`, SOPS-encrypted. Never create Emby keys through the API.
- zvol `tank2/talos-data`: 120G, sparse, `compression=lz4`, `sync=disabled` (same as `tank2/talos`), `volblocksize=16K` *(my call: DB/SQLite pages, the OS disk's 128K would amplify writes)*.
- Talos volume name `data`, mount `/var/mnt/data`, xfs. OS zvol is 500G, data disk 120G: install selector `size: ">= 300GB"`, data selector `disk.size < 300u * GB && !system_disk`.
- StorageClass `local-data`: `openebs.io/local`, `BasePath: /var/mnt/data/openebs`, `WaitForFirstConsumer`, `reclaimPolicy: Retain`, default class. `openebs-hostpath` untouched.
- New PVCs are named `<app>-data`, carry `kustomize.toolkit.fluxcd.io/prune: disabled`, same size as today.
- Data-disk snapshots: hourly at minute 5 (keep 48 h) + daily 03:00 (keep 14 d), same minutes as the `tank2/talos` tasks; replicated to `tank/talos-data`.
- Repo rules (AGENTS.md): no domain or public IPs in git/PRs, no Co-Authored-By trailers, no `automerge` label, `talos:apply` / TrueNAS `sudo` / anything destructive is run by the user, SOPS via `mise exec -- sops`, media titles never printed.
- whosaid Postgres ends at **1 instance**.

## Review Focus

1. **Someone starts playing in Emby during a cutover** → the move must not stop the app; `move-volume.sh` re-checks `emby-idle.sh` right before scaling to 0 (Task 4 Step 3 test).
2. **rsync pass 2 counts differ / app fails on the new PVC** → the app stays stopped on the old claim, no resume; rollback = revert the PR (Task 4 dry run of a failing count).
3. **The data disk is missing or not mounted at boot** → `local-data` volumes must not silently land on the OS disk: the StorageClass BasePath is under `/var/mnt/data`, and Task 3 checks `/var/mnt/data` is a separate mount before any app moves.
4. **CNPG scale-down drops the wrong instance** → only scale back once the new instance is primary (`status.currentPrimary`), Task 6 checks it before `instances: 1`.
5. **node:down after Longhorn is gone** → discovery by any PVC must still find every stateful app and wait for its pods to stop (Task 7 dry-run lists the same apps as today plus the NFS-config ones that moved).

Reads the key with `kubectl -n media get secret emby-maintenance -o jsonpath='{.data.api-key}' | base64 -d`, reaches Emby through a short `kubectl port-forward svc/emby <local>:10079`.

- [ ] **Step 3:** After merge + Flux apply: `scripts/emby-idle.sh; echo $?` → `0` with "playing: 0" when idle. With a wrong key (`EMBY_KEY_OVERRIDE=bad`, an env override the script honors for testing) → exit 2.

- Create: `scripts/move-volume.sh`

**Interfaces:**
- Produces: `scripts/move-volume.sh <namespace> <helmrelease> <deployment> <source> <dest-pvc> <pr> [--exclude DIR]...` where `<source>` is `pvc:<name>` or `nfs:<path>`. Flow (from scratchpad `cutover.sh` + `rsync-pass.sh`): suspend HR → wait PR checks green → merge → reconcile → wait `<dest-pvc>` exists (it stays Pending until the rsync pod binds it) → rsync pass 1 live (pod as 568:568 mounting source read-only + dest) → `emby-idle.sh --wait 60` → scale to 0 → pass 2 `--delete` → compare file counts (stop, no resume, if different) → resume HR → rollout status → check the deployment's volume uses `<dest-pvc>`. Logs to `.state/move-volume.log`.

- [ ] **Step 1:** Add the StorageClass (Global Constraints values, annotation `storageclass.kubernetes.io/is-default-class: "true"`, OpenEBS `cas.openebs.io/config` with `BasePath`) and flip Longhorn's default.

- [ ] **Step 3:** Test the guards with `--dry-run` and a fake: `EMBY_IDLE_CMD=false scripts/move-volume.sh … --dry-run` stops before scaling with "Emby busy"; a count-mismatch path is covered by `MOVE_FAKE_COUNTS="10 9"` → stops with "counts differ, NOT resuming".
- [ ] **Step 4:** Commit, PR, merge. Check: `kubectl get sc` shows only `local-data` as `(default)`. Smoke test: a throwaway PVC + busybox pod in `default` writes a file; on the node the PV path is under `/var/mnt/data/openebs/`; delete pod, PVC, and the Retained PV + its folder (via a cleanup pod).
